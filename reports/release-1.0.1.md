## 신규 설치

1. ZIP의 SHA-256을 동봉 파일과 대조한다.
2. ZIP을 전용 마켓플레이스 루트의 `plugins/` 아래에 해제한다.
3. 동봉 `marketplace.json`을 해당 루트의 `.agents/plugins/marketplace.json`으로 둔다.
4. 해당 마켓플레이스를 Codex에 등록하고 `devotional-shorts-prep@devotional-shorts`를 설치한다.
5. 새 Codex 작업을 시작하고 비운영 본문으로 로컬 DRAFT 생성을 확인한다.
6. Telegram 사용 시 `OPERATIONS.md`의 외부 인수 게이트를 수행한다.

## 기존 1.0.0 업데이트

현재 설치본의 배포 도구로 새 ZIP을 먼저 검증한 뒤 `extract --update`로 교체하고 플러그인을 다시 설치한다. `jobs/`는 플러그인 외부의 프로젝트 데이터이므로 교체 대상에 포함하지 않는다. 업데이트 후 새 Codex 작업에서 `1.0.1`을 확인한다.

## 운영 승인 기준

다른 사용자가 실제 운영을 시작하려면 다음을 모두 만족해야 한다.

1. 전용 봇과 전용 그룹을 사용하고 활성 웹훅이 없어야 한다.
2. 승인 대기 작업과 조회 실행자는 봇당 하나여야 한다.
3. preflight, 보고 전송, 현재 메시지 직접 답장 승인, 승인 확인이 성공해야 한다.
4. 승인 전 이미지 미생성과 승인 후 제한된 테스트 이미지 전달을 확인해야 한다.
5. `jobs/` 접근 권한, 백업, 기본 90일 보존과 월간 복원 검증 담당자를 기록해야 한다.

## 롤백

설치 교체가 실패하면 업데이트 도구가 기존 설치본을 복원한다. 이미 생성된 `jobs/`는 삭제하거나 자동 변환하지 않는다. 운영 중 문제가 발견되면 새 보고·승인·이미지 전달을 중단하고 기존 `1.0.0` 설치본으로 되돌린 뒤 작업 상태와 Telegram 그룹을 대조한다.
