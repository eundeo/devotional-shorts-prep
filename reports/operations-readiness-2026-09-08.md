# 2026-09-08 사용 준비·배포·운영 보완 결과

## 결론

점검에서 확인한 내부 보완사항은 플러그인 `1.0.1`에 반영하고 검증했다. 로컬 제작과 배포 패키지 설치는 준비 완료다. 실제 Telegram 운영은 사용자별 환경변수 설정과 테스트 그룹 인수 후 시작한다. GitHub 배포 대상은 비공개 저장소 `eundeo/devotional-shorts-prep`으로 정했다.

이번 작업에는 승인 흐름·전송 복구 안전성 수정, 회귀 테스트, ZIP 내 독립 운영 안내 추가, 결정적 배포 패키지 생성, 신규·업데이트 설치 검증이 포함된다. 콘텐츠 방법론과 데이터 스키마는 변경하지 않았다.

## 사용할 수 있는 범위

- 로컬 원고·장면 계획·검토 보고서: 현재 사용자 환경에 `1.0.1` 설치·활성화 완료, 새 Codex 작업에서 바로 사용 가능
- ZIP을 통한 다른 사용자 신규 설치와 `1.0.0` 설치본 업데이트: 검증 완료
- Telegram 보고·승인·이미지 전달: 각 사용자의 비밀 환경변수 설정, 전용 봇·그룹 준비, 실제 preflight와 테스트 그룹 인수 후 사용
- 이미지 생성: 현재 리비전 승인과 사용 가능한 이미지 도구가 있을 때 사용
- GitHub 비공개 배포: `eundeo/devotional-shorts-prep`에 소스·태그·릴리스 자산 게시 완료; 지인 초대 대기

## 남은 외부 인수 게이트

1. 운영자가 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_APPROVER_IDS`를 Codex 실행 환경에 주입한다.
2. 전용 테스트 그룹에서 preflight, 보고, 현재 메시지 직접 답장, 승인 확인, 이미지 한 건 전달을 순서대로 확인한다.
3. 운영 데이터 담당자·백업 위치·보존 예외를 조직 기준에 맞게 확정한다.
4. 비공개 저장소에 지인을 초대하고 Windows 설치 인수를 완료한다.

비밀정보와 게시 대상 정보 없이는 위 항목을 대신 완료할 수 없다. 이는 내부 구현 미해결이 아니라 사용자 환경별 배포 인수 단계다.

## 운영상 중요 제한

- 봇 하나에는 승인 대기 작업 하나와 조회 실행자 하나만 둔다.
- 활성 웹훅이 있는 봇은 preflight에서 차단되며 자동 삭제하지 않는다.
- 전송 API 오류가 응답 유실인지 실제 실패인지 알 수 없으면 재실행 전에 Telegram 그룹과 로컬 작업 상태를 대조한다.
- `jobs/`에는 답장 원문과 사용자 ID가 포함될 수 있으므로 소스나 ZIP처럼 공개하지 않는다.
- 설치·업데이트 후에는 새 Codex 작업에서 스킬을 로드한다.

자세한 배포 산출물과 실행 순서는 [1.0.1 배포 준비 보고서](release-1.0.1.md), 사용자 운영 절차는 [플러그인 운영서](../plugins/devotional-shorts-prep/OPERATIONS.md)를 따른다.
