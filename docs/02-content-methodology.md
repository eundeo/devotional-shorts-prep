# 콘텐츠 제작 방법론

## 목적

묵상 본문에서 묵상 포인트와 쇼츠 스크립트를 만드는 방식을 일관된 규칙으로 정의한다. 이 문서는 Claude 공유 대화에서 반복적으로 확정된 작업 방식을 실행 가능한 기준으로 정리한 것이며, 대화 원문 자체를 런타임 의존성으로 사용하지 않는다.

## 선행 조건

- 본문 전문이 입력되어야 한다.
- 사용 가능한 경우 본문 위치와 사용자 특별 지시를 함께 받는다.
- 실행 시점의 `method_version`과 방법론 문서 해시가 정해져 있어야 한다.
- 외부 인용을 사용할 경우 출처 확인 수단이 있어야 한다.

## 확정 요구사항

### 1. 입력 본문 분석 원칙

1. 본문 전체를 먼저 읽고 문학적 단락과 사건 흐름을 파악한다.
2. 앞뒤 문맥이 이해에 필수적인지 판단한다.
3. 당시 청중, 장소, 역사적 배경을 본문 이해에 필요한 범위에서만 설명한다.
4. 복음주의적 성경 이해를 기본으로 하되, 본문이 직접 말하지 않는 내용을 사실처럼 단정하지 않는다.
5. 그리스도 중심 적용은 본문과 정경적 연결이 뒷받침될 때 사용한다.
6. 본문 위치가 없으면 장절을 추측하지 않고 내용 중심으로 해설한다.
7. 행동이 기록되어 있어도 본문이 밝히지 않은 인물의 내면 동기, 감정, 믿음의 깊이를 사실처럼 단정하지 않는다.
8. 바로 앞뒤 문맥이 해석 방향을 실질적으로 바꿀 수 있으면 확인하고, 여러 책임 있는 해석이 가능한 본문은 공통으로 확인되는 의미를 중심에 둔다.

### 2. 주장 분류

생성 내용은 다음 네 범주를 내부적으로 구분한다. 보고서에서는 문장이 자연스럽게 이어지게 쓰되, 근거 수준을 혼동하지 않는다.

| 범주 | 기준 |
| --- | --- |
| 본문 | 입력된 본문이 명시적으로 말하는 사실과 표현 |
| 해석 | 문맥과 복음주의적 주해를 통해 설명한 의미 |
| 추론 | 본문에 직접 쓰이지 않았으나 정황상 도출한 설명 |
| 적용 | 오늘의 삶과 신앙에 연결한 질문과 실천 |

추론에는 `보인다`, `생각할 수 있다`, `시사한다`와 같이 근거 수준을 드러내는 표현을 사용한다. 본문과 다른 성경 구절이 명확히 뒷받침할 때만 단정형을 사용한다.

### 3. 묵상 포인트 구성

묵상 포인트는 다음 순서를 고정한다.

1. **본문 배경**: 본문 이해에 필요한 인물, 사건, 앞뒤 문맥을 2~4문장으로 설명한다.
2. **핵심 해석**: 본문이 드러내는 하나님, 인간, 믿음 또는 복음의 의미를 설명한다.
3. **핵심 묵상 문장**: 전체 원고를 관통하는 한 문장으로 작성한다.
4. **오늘의 적용**: 현대인이 경험하는 구체적 상황과 연결한다.
5. **적용 질문**: 시청자가 자신을 돌아보도록 1~2개의 질문을 제시한다.

핵심 묵상 문장은 짧고 기억 가능해야 하며, 본문을 과장하거나 일반적인 자기계발 문구로 바꾸지 않는다.

오늘의 적용에는 오늘 또는 이번 주에 실행할 수 있는 낮은 위험의 행동을 하나 이상 포함한다. 돈, 가난, 질병, 학대, 권력관계처럼 취약한 청자에게 해를 줄 수 있는 본문은 필수 생활비 포기, 빚, 치료 중단, 학대 인내를 권하지 않고 적용 자체를 안전하게 설계한다.

### 4. 오프닝 질문 자동 선택

- 핵심 묵상 문장을 바탕으로 서로 중복되지 않는 질문 10개를 만든다.
- 예·아니오로 끝나는 질문만 반복하지 않고 경험, 두려움, 선택, 관계, 믿음을 다양한 각도에서 묻는다.
- 다음 기준으로 100점 만점 평가 후 최고 점수를 선택한다.
  - 본문과 핵심 문장 충실도 30점
  - 첫 3초의 호기심 25점
  - 신자·비신자 접근성 20점
  - 낭독 자연스러움 15점
  - 선정적 왜곡이 없는가 10점
- 최고 점수 1개를 최종안으로, 다음 점수 3개를 보고서 대안으로 제공한다.
- 동점이면 본문 충실도, 접근성, 낭독 자연스러움 순으로 우선한다.

### 5. 썸네일 문구 자동 선택

- 핵심 묵상 문장을 압축한 후보 10개를 만든다.
- 한 화면에서 즉시 이해할 수 있는 짧은 구로 쓰고 마침표를 붙이지 않는다.
- 다음 기준으로 100점 만점 평가한다.
  - 본문과 핵심 문장 충실도 30점
  - 즉시 이해 가능성 25점
  - 간결성 20점
  - 호기심 15점
  - 과장·공포 조장이 없는가 10점
- 최고 점수 1개와 대안 3개를 오프닝과 같은 방식으로 제공한다.

### 6. 스크립트 고정 구조

스크립트는 아래 순서를 바꾸지 않는다.

1. 핵심 문장
2. 썸네일 문구
3. 오프닝 질문 1~2줄
4. 본문으로 연결하는 다리 문장
5. 처음 듣는 사람에게 필요한 경우 본문 배경 2줄 이내
6. 기본 3줄의 본문 요약과 가능한 장절 표기
7. 본문 해석과 삶의 적용
8. 핵심 문장 재강조와 적용 질문
9. 3줄 이내의 짧은 기도
10. 고정 CTA

고정 CTA는 다음 문장을 그대로 사용한다.

> 이 영상이 도움이 되셨다면 좋아요와 구독으로 응원해주시고, 생각난 분들에게 이 영상을 공유해주시기 바랍니다.

### 7. 문체와 낭독성

- 문장 종결은 `다`, `나`, `까`를 사용하고 `요`체를 사용하지 않는다.
- 친근하지만 지나치게 사적인 친구 말투가 아닌 설교형 낭독체를 사용한다.
- 신학 전문용어는 처음 듣는 사람도 이해하도록 풀어 쓴다.
- 한 문장을 지나치게 길게 연결하지 않는다.
- 본문 요약은 사건과 감정이 그려지도록 구체적으로 쓰되 본문에 없는 장면을 사실로 만들지 않는다.
- 결론에서는 핵심 문장을 다시 들려주고 시청자의 삶을 향한 질문으로 연결한다.

### 8. 분량 정책

- 공백을 제외한 한글·영문·숫자 5자를 낭독 1초로 추정한다.
- 목표 구간은 100~120초다.
- 120초를 넘으면 먼저 중복 설명과 수식어를 줄인다.
- 본문 배경을 제거하면 초심자의 이해가 훼손되는 경우에만 121~150초를 허용한다.
- 예외를 사용하면 `duration_exception: true`와 한 문장 사유를 보고서에 표시한다.
- 150초를 넘는 결과는 완료 결과로 인정하지 않고 다시 압축한다.

### 9. 성경 장절 표기

- 현재 본문과 같은 성경 안의 복수 구절은 `(22:51, 23:8-10)`처럼 장절만 표기한다.
- 다른 성경을 인용하면 `(롬 5:8)`처럼 통용 약칭과 장절을 함께 적는다.
- 입력에서 장절을 확인할 수 없으면 임의로 장절을 생성하지 않는다.
- 보조 구절은 핵심 해석을 실제로 뒷받침할 때만 사용한다.

### 10. 외부 인용 검증

- 신학자, 목회자, 작가, 유명인의 직접 인용은 원문과 저자·출처를 확인할 수 있을 때만 사용한다.
- 보고서에 저자, 출처명, 확인 URL 또는 서지정보를 기록한다.
- 번역한 인용은 `번역`임을 표시하고 원문의 의미를 과장하지 않는다.
- 출처를 확인할 수 없거나 기억에 의존해야 하면 인용을 생략한다.
- 인용이 없어도 스크립트가 완결되도록 작성한다.

### 11. 사용자 지시 우선순위

충돌 시 다음 순서를 적용한다.

1. 안전, 승인 게이트, 사실 검증 규칙
2. 사용자가 현재 작업에 명시한 특별 지시
3. 버전이 지정된 제작 방법론
4. 승인 예시에서 관찰되는 선호
5. 모델의 일반적 작성 선호

사용자의 신학적 강조는 본문과 충돌하지 않는 범위에서 반영한다. 특정 부분만 수정하라는 요청은 해당 범위만 변경하고 나머지 승인 내용을 그대로 보존한다.

### 12. 의미 품질 게이트

결정적 구조 검사와 별도로 본문 충실도, 해석 명료성, 복음주의적 일관성, 낭독 자연스러움, 적용 구체성을 각각 1~5점으로 평가한다. 각 축 4점 이상, 평균 4.2점 이상이어야 담당자 보고 가능한 결과로 인정한다. 본문이 밝히지 않은 내면·동기 단정, 위해 가능한 적용, 미검증 인용이나 장절은 평균과 관계없이 실패다. 실패 축만 한 번 수정하고 다시 평가하며, 두 번째에도 기준을 못 넘으면 저장·보고하지 않는다.

## 승인 예시 관리

- 새로 승인된 원고는 자동으로 방법론 규칙이 되지 않는다.
- 반복 가능한 패턴인지 사람이 검토한 뒤 `references/examples.md`에 추가한다.
- 규칙 변경이 필요한 경우 `references/method.md`를 수정하고 방법론 버전을 올린다.
- 예시는 입력, 핵심 묵상 문장, 최종 스크립트, 승인된 이유를 함께 기록한다.
- 아직 제공되지 않은 승인 원고는 `추후 추가할 검증 자료`이며 구현을 막는 미결정 사항이 아니다.

## 예외 처리

- 본문과 사용자 해석이 충돌하면 본문 근거와 사용자 관점을 구분해 보고한다.
- 검증할 수 없는 인용은 삭제하고 연결 문장을 자연스럽게 다시 쓴다.
- 오프닝 또는 썸네일 후보가 서로 실질적으로 같으면 중복 후보를 교체한 뒤 평가한다.
- 필수 섹션이 누락되면 보고 전 자체 수정 단계를 한 번 수행한다.
- 일부만 수정할 때 분량이 초과되면 변경한 부분을 우선 압축하고 승인된 다른 부분은 보존한다.

## 완료 기준

- 묵상 포인트 다섯 항목과 스크립트 열 항목이 모두 생성된다.
- 최종 오프닝·썸네일과 각 대안 3개가 제공된다.
- 문체, 분량, 장절, 인용, CTA 규칙을 통과한다.
- 본문 사실과 해석적 추론이 혼동되지 않는다.
- 본문이 밝히지 않은 인물의 내면과 동기를 단정하지 않는다.
- 구체적이고 낮은 위험의 적용이 하나 이상 존재한다.
- 의미 품질 다섯 축이 각각 4점 이상이고 평균 4.2점 이상이다.
- 적용한 방법론 버전과 해시가 작업 데이터에 기록된다.
