# 콘텐츠 생성 워크플로

## 목적

본문 입력부터 묵상 포인트, 쇼츠 스크립트, 이미지 프롬프트, 로컬 보고서 생성까지의 순서를 정의한다. 이 단계는 이미지를 생성하지 않으며 담당자가 승인할 수 있는 완성된 초안을 만드는 데서 끝난다.

## 선행 조건

- `references/method.md`에 유효한 방법론 버전이 기록되어 있다.
- 입력에 `passage_text`가 포함되어 있다.
- 작업 프로젝트의 `jobs/` 경로에 쓸 수 있다.
- [데이터 및 상태 설계](04-data-and-state-design.md)의 스키마를 사용할 수 있다.

## 확정 요구사항

### 1단계: 입력 검증과 정규화

1. 본문 앞뒤 공백을 제거하고 줄바꿈을 보존한다.
2. 본문이 비어 있으면 작업 ID를 만들지 않고 종료한다.
3. 장절, 제목, 날짜, 특별 지시, 시각 지시를 별도 필드로 분리한다.
4. 본문 위치가 없으면 `passage_reference: null`로 유지한다.
5. 입력 원문은 수정하지 않고 `job.json`에 그대로 보존한다.
6. 새 작업 ID와 `r001` 리비전 폴더를 만든다.

수정 요청으로 새 리비전을 만들 때는 원래 입력과 이전 리비전을 복사하지 않는다. 새 리비전은 `job.json`에서 이전 데이터를 참조하고 변경 결과만 자신의 리비전 항목과 파일에 저장한다.

### 2단계: 방법론 로드

1. 플러그인에 포함된 `references/method.md`를 읽는다.
2. 문서에 선언된 의미적 버전을 `method.version`으로 저장한다.
3. 실제 파일 바이트의 SHA-256을 `method.sha256`으로 저장한다.
4. 전체 파일을 현재 리비전의 `method-snapshot.md`로 복사한다.
5. 방법론 파일이 없거나 버전을 읽을 수 없으면 생성 작업을 시작하지 않는다.

### 3단계: 본문 배경·문맥·주해 생성

1. 본문의 사건, 인물, 논리 흐름을 요약한다.
2. 앞뒤 문맥이 없으면 이해하기 어려운 부분을 식별한다.
3. 본문이 직접 말하는 내용과 해석을 구분한다.
4. 복음주의적 관점에서 핵심 의미를 설명한다.
5. 본문에 근거하지 않은 세부 장면과 심리를 사실로 단정하지 않는다.
6. 보조 성경 구절은 핵심 해석에 필요한 경우만 추가한다.

결과는 `devotional_points.background`와 `devotional_points.interpretation`에 저장한다.

### 4단계: 핵심 묵상 문장과 적용 생성

- 전체 본문을 하나의 기억 가능한 핵심 문장으로 압축한다.
- 핵심 문장은 본문 해석과 모순되지 않아야 한다.
- 현대인의 관계, 선택, 두려움, 풍요, 결핍, 믿음 등 본문과 실제로 연결되는 상황으로 적용한다.
- 적용 질문은 1~2개로 제한한다.
- 결과를 `core_sentence`, `application`, `application_questions`에 저장한다.

### 5단계: 오프닝과 썸네일 후보 생성

1. 핵심 문장을 바탕으로 오프닝 질문 10개를 생성한다.
2. 의미가 실질적으로 겹치는 후보를 교체한다.
3. 방법론의 100점 기준으로 각각 평가한다.
4. 최고 점수 1개를 선택하고 다음 3개를 대안으로 저장한다.
5. 같은 방식으로 썸네일 문구 10개를 생성·평가한다.
6. 동점이면 방법론에 정의된 우선순위로 결정한다.

이 단계에서 제작자에게 선택을 요청하지 않는다. 선택 결과와 대안은 최종 보고서에서 담당자가 검토한다.

### 6단계: 고정 구조 스크립트 생성

다음 순서로 작성한다.

1. 선택된 오프닝 질문을 1~2줄로 배치한다.
2. 오프닝에서 본문으로 넘어가는 다리 문장을 작성한다.
3. 초심자의 이해에 필요한 경우에만 2줄 이내의 배경 설명을 넣는다.
4. 본문 흐름을 기본 3줄로 생생하게 요약한다.
5. 핵심 해석을 오늘의 삶과 연결한다.
6. 핵심 문장을 다시 강조하고 적용 질문을 제시한다.
7. 3줄 이내의 짧은 기도를 작성한다.
8. 고정 CTA를 마지막에 원문 그대로 붙인다.
9. 각 섹션과 섹션을 합친 `full_text`를 모두 저장한다.

스크립트 본문에는 내부 평가 점수, 작성 지시, `본문·해석·추론`과 같은 제작 메타데이터를 노출하지 않는다.

### 7단계: 의미 품질 평가와 자체 검수

먼저 본문 충실도·해석 명료성·복음주의적 일관성·낭독 자연스러움·적용 구체성을 각각 1~5점으로 평가하고 한 문장 근거를 남긴다. 각 축 4점 이상, 평균 4.2점 이상, 즉시 실패 조건 0건일 때만 아래 구조 검사로 넘어간다. 기준 미달 축만 한 번 수정하고 전체를 재평가하며, 다시 실패하면 저장·보고하지 않는다.

구조 검수는 다음 순서로 진행하고, 실패한 항목만 한 번 자체 수정한다.

| 검사 | 통과 기준 |
| --- | --- |
| 구조 | 필수 10개 섹션 존재, 순서 일치 |
| 문체 | 종결이 `다·나·까` 중심이며 `요`체 없음 |
| CTA | 고정 CTA와 완전히 일치 |
| 장절 | 확인하지 못한 장절을 만들지 않음 |
| 인용 | 직접 인용마다 검증 출처 존재 |
| 충실도 | 핵심 문장과 적용이 본문 해석을 왜곡하지 않음 |
| 길이 | 기본 120초 이하, 예외도 150초 이하 |
| 대안 | 오프닝·썸네일 최종안 각 1개와 대안 각 3개 |

분량은 `공백 제외 한글·영문·숫자 수 ÷ 5`를 반올림해 초 단위로 계산한다. 120초를 넘으면 중복 설명, 수식어, 같은 의미의 적용 문장을 순서대로 줄인다. 필수 배경을 유지해야만 하는 경우 `duration_exception`과 사유를 기록한다.

### 8단계: 이미지 프롬프트 분할

1. 실제로 낭독하는 `full_text`를 섹션과 문장 단위로 나눈다.
2. 핵심 문장과 썸네일 같은 메타 표시가 낭독문에 중복 포함되면 실제 낭독되는 부분만 사용한다.
3. 완결된 문장을 순서대로 누적해 공백 제외 20자 이상이 되는 순간 장면을 확정한다.
4. 마지막 누적분이 20자 미만이어도 별도 장면으로 확정한다.
5. 각 장면의 시대, 한국어 시각 설명, 영어 프롬프트를 생성한다.
6. 장면 번호, 원문, 프롬프트 해시와 `PENDING` 상태를 저장한다.

이 단계의 산출물은 프롬프트이며 실제 이미지 파일이 아니다.

### 9단계: 보고서 작성

`report.md`는 다음 순서를 고정한다.

1. 제목과 승인 요약: 리비전, 예상 시간, 장면 수, 작업 ID, 본문 위치
2. 한눈에 보기: 핵심 문장, 선택된 오프닝과 썸네일
3. 섹션별 최종 스크립트: 오프닝, 본문 요약, 해석과 적용, 결론과 질문, 기도, 고정 CTA
4. 공통 제작 기준과 장면별 사용 문장·한국어 설명·최종 영어 프롬프트
5. 오프닝과 썸네일 대안 각 3개
6. 자체 검수, 의미 품질 평균, 분량, 출처, 확인이 필요한 사항
7. 담당자 답장 안내

입력 본문 전문, 묵상 포인트의 중간 분석, 의미 품질 축별 상세 근거, 방법론 버전·해시는 `job.json`과 `method-snapshot.md`에 보존하고 담당자 보고서에 반복하지 않는다. 제목과 본문 위치가 모두 없으면 썸네일 최종안을 보고서 제목으로 사용한다.

답장 안내에는 `이 보고 메시지에 직접 답장하여 승인, 수정 요청 또는 보류 의견을 남겨주십시오`라는 의미가 분명히 포함되어야 한다.

### 10단계: 로컬 저장과 상태 확정

1. 리비전 폴더에 `report.md`와 `method-snapshot.md`를 저장한다.
2. `job.json` 리비전 항목에 생성 결과 전체를 기록한다.
3. 상태를 `DRAFT`로 설정한다.
4. JSON과 보고서가 다시 읽히는지 확인한다.
5. 성공하면 [텔레그램 승인 워크플로](06-telegram-approval-workflow.md)의 보고 단계로 넘긴다.

### 수정 요청 처리

- 수정 의견을 변경 대상과 보존 대상으로 분리한다.
- 이전 리비전의 각 섹션 해시를 기준으로 변경 대상 외의 섹션을 그대로 복원한다.
- 변경이 전체 핵심 문장에 영향을 주면 오프닝, 썸네일, 해석, 적용, 장면 프롬프트도 재생성한다.
- 단순 문구 수정처럼 영향 범위가 한정되면 해당 섹션과 그 문장을 포함한 이미지 장면만 바꾼다.
- 새 리비전은 항상 다시 자체 검수하고 새 보고서로 승인받는다.

## 예외 처리

| 상황 | 처리 |
| --- | --- |
| 본문 장절 없음 | `본문 위치 미확인` 표시, 장절 추측 없이 계속 |
| 외부 인용 검증 실패 | 인용 삭제 후 연결 문장 재작성 |
| 120초 초과 | 압축 후 재검수, 필수 배경인 경우만 150초까지 예외 |
| 150초 초과 | 보고하지 않고 다시 압축 |
| 사용자 지시와 방법론 충돌 | 안전·사실 검증을 지키고 현재 작업의 명시 지시 우선, 충돌 내용 보고 |
| 필수 섹션 누락 | 한 번 자체 수정, 계속 누락되면 작업 중단 및 오류 기록 |
| 특정 부분만 수정 | 비대상 섹션 보존, 영향받는 장면만 다시 분할 |
| 로컬 저장 실패 | 텔레그램 전송 금지, 임시 파일 정리 후 오류 보고 |

## 완료 기준

- 본문 입력만으로 `DRAFT` 상태의 `job.json`과 `report.md`가 생성된다.
- 방법론 버전·해시·스냅샷이 모두 일치한다.
- 필수 묵상 포인트와 스크립트 구조가 빠짐없이 존재한다.
- 오프닝·썸네일 최종안과 대안이 자동 선정된다.
- 이미지 프롬프트와 예상 장면 수가 생성되지만 이미지 파일은 존재하지 않는다.
- 의미 품질 통과 여부·평균, 자체 검수 결과와 예외 사유가 보고서에 반영되며 축별 점수·근거는 `job.json`에 보존된다.
