# 테스트 및 인수 계획

## 목적

콘텐츠 구조, 승인 안전성, 파일 상태, 외부 연동, 신규 사용자 설치를 자동·수동 테스트로 검증한다. 생성형 결과의 의미 품질과 결정 가능한 구조 규칙을 분리해 평가한다.

## 선행 조건

- [데이터 및 상태 설계](04-data-and-state-design.md)의 스키마와 상태가 구현되어 있다.
- 단계별 기능은 [구현 로드맵](08-implementation-roadmap.md)의 게이트를 통과한다.
- 텔레그램 테스트 그룹과 실제 운영 그룹은 분리한다.
- 외부 API 테스트 전에는 모의 응답으로 실패 경로를 검증한다.

## 확정 요구사항

### 테스트 계층

| 계층 | 대상 | 외부 API |
| --- | --- | --- |
| 정적 검증 | 파일 구조, 필수 섹션, 설정 누락, 비밀정보 | 사용 안 함 |
| 단위 테스트 | 분량, 장면 분할, 상태 전이, 응답 집계, 멱등성 | 모의 처리 |
| 통합 테스트 | 작업 생성, 보고서 렌더링, 텔레그램 요청·응답, 이미지 파일 처리 | 기본 모의 처리 |
| 의미 품질 평가 | 본문 충실도, 복음주의적 해석, 적용 자연스러움 | 필요 시 출처 검증 |
| 종단간 테스트 | 본문 입력부터 이미지 전달 | 테스트 그룹·ImageGen 사용 |
| 설치 인수 테스트 | 신규 사용자 설치와 설정 | 테스트 사용자 설정 사용 |

### 기준 입력 세트

다음 특성을 각각 포함하는 비공개 테스트 본문 세트를 준비한다.

1. 사건 흐름이 분명한 짧은 본문
2. 앞뒤 배경 설명이 필수적인 본문
3. 풍요·결핍처럼 현대 적용이 중심인 본문
4. 본문 위치가 없는 전문 입력
5. 다른 성경 보조 구절이 필요한 본문
6. 외부 인용을 요청하지만 출처를 확인할 수 없는 입력
7. 특정 화풍과 현대 인물 구성을 지정한 입력
8. 기존 원고의 한 부분만 수정하라는 피드백

향후 담당자가 승인한 원고는 `추후 추가할 검증 자료`로서 회귀 세트에 추가한다. 승인 원고가 없더라도 구조·안전·상태 테스트는 모두 구현하고 실행할 수 있어야 한다.

문체 검사는 단순히 문자열 `요` 전체를 금지하지 않는다. `요한복음`처럼 단어 일부에 포함된 경우를 제외하고 문장 끝의 `요`, `요.`, `요?`, `요!`를 검사한다.

### 의미 품질 평가

자동 구조 검사를 통과한 결과를 다음 5점 척도로 평가한다.

| 평가축 | 1점 | 5점 |
| --- | --- | --- |
| 본문 충실도 | 본문을 왜곡하거나 없는 사실을 단정 | 본문과 문맥을 정확히 반영 |
| 해석 명료성 | 본문·추론·적용이 혼재 | 근거 수준이 명확함 |
| 복음주의적 일관성 | 핵심 신앙 내용과 충돌 | 본문에 근거한 복음적 해석 |
| 낭독 자연스러움 | 문어체·장문으로 듣기 어려움 | 자연스럽고 리듬이 좋음 |
| 적용 구체성 | 일반적 자기계발 문구 | 본문에서 삶으로 구체적 연결 |

각 축 4점 이상, 평균 4.2점 이상을 기준 원고 승인 조건으로 사용한다. 기준을 못 넘으면 방법론 또는 생성 지침을 조정하고 방법론 버전을 올린다.

### 승인 전 이미지 방지 테스트

ImageGen 호출 모의 객체의 호출 횟수를 검사한다. 다음 모든 경우 호출 횟수는 0이어야 한다.

- `DRAFT`
- `SENT_FOR_APPROVAL`
- `REVISION_REQUESTED`
- `HOLD`
- 불명확 답장만 존재
- 미등록 사용자의 승인
- 이전 메시지 또는 이전 리비전 승인
- 승인 이후 스크립트나 프롬프트 해시 변경
- 보고 후 24시간 초과

`APPROVED`이며 모든 해시와 메시지 ID가 일치할 때만 장면 수만큼 호출한다.

### 이미지 실패와 복구 테스트

- 첫 실패·두 번째 성공: 장면 `GENERATED`, 시도 횟수 2
- 두 번 실패: 장면 `FAILED`, 작업 `NEEDS_REVIEW`
- 일부 실패: 성공 파일과 메시지 ID 보존
- 실패 장면 재개: 실패 장면만 호출
- 텔레그램만 실패: 이미지 재생성 없이 전달만 재시도
- 전체 전달 완료: 모든 장면 `DELIVERED`, 작업 `DELIVERED`

### 종단간 테스트

1. 테스트 프로젝트와 텔레그램 그룹을 준비한다.
2. 본문 위치가 포함된 기준 본문을 입력한다.
3. 로컬 `DRAFT` 결과와 이미지 파일 부재를 확인한다.
4. 보고서를 전송하고 `SENT_FOR_APPROVAL`을 확인한다.
5. 담당자가 수정 요청을 보내 새 리비전과 이전 리비전 보존을 확인한다.
6. 새 보고서를 전송하고 명확한 승인을 보낸다.
7. 승인 확인 전 이미지 파일 부재를 다시 확인한다.
8. 승인 확인을 실행해 장면 이미지를 생성한다.
9. 로컬 파일과 텔레그램 장면 순서를 비교한다.
10. 최종 `DELIVERED` 상태와 이벤트 기록을 확인한다.

### 신규 사용자 설치 테스트

- 개발자의 설치본과 환경변수를 사용하지 않는 깨끗한 환경에서 수행한다.
- 플러그인을 GitHub 체크아웃 또는 압축 해제로 설치한다.
- 신규 사용자의 봇·그룹·담당자 설정만 입력한다.
- `preflight`부터 전체 종단간 흐름을 실행한다.
- 경로, 사용자명, 개발자 ID에 대한 숨은 의존성이 없어야 한다.

## 예외 처리

- 생성형 결과가 매 실행마다 문장 단위로 달라도 구조·안전 규칙은 결정적으로 검사한다.
- 외부 API 장애 시 통합 테스트 실패와 제품 결함을 구분해 기록한다.
- 실제 텔레그램·ImageGen 테스트는 모의 테스트가 먼저 통과한 뒤 수행한다.
- 승인 예시가 추가되면 기존 테스트를 삭제하지 않고 회귀 세트에 누적한다.
- 테스트 중 생성한 토큰, 채팅 ID, 사용자 ID를 스냅샷이나 실패 출력에 남기지 않는다.

## 완료 기준

- 정의된 정적·단위·통합 테스트가 모두 통과한다.
- 의미 품질 평가가 각 축 4점 이상, 평균 4.2점 이상이다.
- 테스트 그룹 종단간 시나리오가 완료된다.
- 신규 사용자 설치 테스트와 최종 인수 체크리스트가 모두 통과한다.
