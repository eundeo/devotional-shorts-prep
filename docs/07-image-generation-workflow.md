# 이미지 생성 워크플로

## 목적

현재 리비전이 승인된 이후 장면별 프롬프트로 9:16 이미지를 생성하고, 정상 파일을 프로젝트에 보존한 뒤 담당자에게 전달한다. 승인 전 비용 발생과 잘못된 리비전 생성을 방지하는 것이 최우선이다.

## 선행 조건

- 작업 상태가 `APPROVED`다.
- 승인 기록의 작업 ID, 리비전, 보고 메시지 ID가 현재 값과 일치한다.
- 현재 리비전의 스크립트와 모든 장면 프롬프트 해시가 승인 시점과 같다.
- ImageGen을 사용할 수 있으며 프로젝트의 이미지 폴더에 쓸 수 있다.
- 담당자가 보고서에서 전체 장면 수와 프롬프트를 검토했다.

## 확정 요구사항

### 1. 승인 게이트

이미지 생성 직전에 다음 항목을 모두 검사한다.

1. `job.status == APPROVED`
2. `approval.decision == approved`
3. 승인 리비전과 `current_revision` 일치
4. 승인 보고 메시지 ID와 현재 `report_message_id` 일치
5. 승인 이후 스크립트·장면 수·프롬프트 해시 변경 없음
6. 수정 요청 또는 보류 이벤트가 승인 후 추가되지 않음

하나라도 실패하면 이미지 생성 호출을 0회로 유지하고 새 보고 또는 수동 검토를 요구한다.

### 2. 장면 분할 규칙

- 대상은 실제 낭독 순서의 `script.full_text`다.
- 마침표, 물음표, 느낌표와 한국어 문장 종결을 기준으로 완결 문장을 나눈다.
- 문장을 중간에서 자르지 않는다.
- 공백과 줄바꿈을 제외한 누적 길이가 20자 이상이 되면 장면을 확정한다.
- 20자 미만 문장은 다음 문장과 합친다.
- 마지막 누적분이 20자 미만이어도 하나의 장면으로 남긴다.
- 장면 번호는 1부터 연속으로 부여한다.

원고 수정으로 문장 경계가 달라지면 새 리비전에서 전체 장면을 다시 계산한다. 승인된 리비전 안에서는 장면 경계를 변경하지 않는다.

### 3. 장면 프롬프트 구조

각 장면은 보고서와 ImageGen 호출에 다음 세 내용을 포함한다.

1. **스크립트 원문**: 장면이 표현해야 할 정확한 낭독 문장
2. **한국어 시각 설명**: 인물, 행동, 표정, 공간, 빛, 카메라 구도
3. **영어 생성 프롬프트**: 시대·인물·행동·배경·조명·스타일·9:16 구성

텍스트를 이미지 안에 직접 표시하도록 요청하지 않는다. 성경 장절, 썸네일 글자, 자막은 영상 편집 단계의 책임이며 v1 이미지 생성 범위가 아니다.

### 4. 시대와 배경 구분

| 스크립트 구간 | 기본 설정 |
| --- | --- |
| 성경 사건·인물·본문 요약 | 해당 본문 시대의 고대 근동 또는 이스라엘 배경 |
| 본문 해석 중 성경 사건을 되짚는 부분 | 성경 시대 배경 |
| 오늘의 삶에 직접 적용하는 부분 | 현대 생활 공간과 현대 인물 |
| 기도 | 현대 인물 또는 상징적이되 사실적인 현대 장면 |
| CTA | 따뜻하고 희망적인 현대 공동체 장면 |

시대가 불분명하면 본문이 제공하는 범위 안에서 가장 일반적인 고대 근동 배경을 사용하고, 특정 왕조·도시·복식을 근거 없이 단정하지 않는다.

### 5. 기본 스타일

성경 시대 장면은 다음 공통 스타일을 적용한다.

> photorealistic, hyper-detailed, historically accurate ancient Near Eastern setting, Iron Age Israelite era, medium brightness natural lighting, balanced warm color grading, film-like texture, shallow depth of field, 9:16 vertical composition

본문 시대가 철기 시대 이스라엘과 명백히 다르면 `Iron Age Israelite era`를 본문에 맞는 검증 가능한 시대 표현으로 교체한다.

현대 장면은 다음 공통 스타일을 적용한다.

> photorealistic, hyper-detailed, contemporary Korean setting, medium brightness natural lighting, balanced warm color grading, film-like texture, shallow depth of field, 9:16 vertical composition

- 지나치게 어둡거나 공포 영화 같은 노출을 피한다.
- 따뜻함과 희망을 유지하되 본문의 긴장과 슬픔을 지우지 않는다.
- 모든 장면에서 세로형 주 피사체와 상하 자막 여백을 고려한다.

### 6. 현대 인물 순환

기본 인물 풀은 `20대 남성`, `20대 여성`, `40대 남성`, `40대 여성`, `60대 남성`, `60대 여성`이다.

- 작업 ID SHA-256 첫 바이트를 6으로 나눈 나머지를 시작 위치로 사용한다.
- 현대 장면이 나올 때마다 풀을 순환한다.
- 바로 앞 현대 장면과 같은 연령대·성별 조합을 반복하지 않는다.
- 장면 의미상 가족, 부부, 공동체가 필요하면 여러 연령과 성별을 함께 사용한다.
- 사용자가 특정 인물을 지정하면 해당 작업에서는 지정이 우선한다.

### 7. 시각 지시 우선순위

1. 이미지 안전과 승인 게이트
2. 현재 작업의 구체적인 장면 지시
3. 현재 작업의 화풍 지시
4. 본문 시대 정확성
5. 기본 공통 스타일
6. 인물 순환 기본값

특정 화풍이 지정되면 사실적 기본 스타일을 교체할 수 있지만 9:16, 장면 내용, 밝기 요구는 명시적으로 취소되지 않는 한 유지한다.

### 8. 생성 순서와 저장

1. 상태를 `GENERATING`으로 바꾸고 이벤트를 기록한다.
2. 장면 번호 순으로 한 장씩 생성한다.
3. 반환 파일의 실제 형식과 파일 무결성을 확인한다.
4. `revisions/rNNN/images/scene-NNN.<ext>`에 먼저 저장한다.
5. 저장한 파일의 해시와 프롬프트 해시를 장면 데이터에 기록한다.
6. 장면 상태를 `GENERATED`로 바꾼다.
7. 로컬 저장에 성공한 파일만 텔레그램으로 보낸다.
8. 전송 성공 메시지 ID를 기록하고 장면 상태를 `DELIVERED`로 바꾼다.

이미지 생성은 v1에서 순차 실행한다. 한 장의 실패가 다른 장면 결과를 손상시키지 않으며 생성 순서와 보고서 장면 번호가 일치한다.

### 9. 재시도와 부분 실패

- 첫 생성 실패 시 같은 승인 프롬프트로 한 번만 재시도한다.
- 두 번째 실패 후 장면을 `FAILED`, 작업을 `NEEDS_REVIEW`로 설정한다.
- 성공한 로컬 파일과 텔레그램 메시지 ID는 유지한다.
- 재개 명령은 `FAILED` 장면만 대상으로 한다.
- 프롬프트를 수정하지 않는 재시도는 새 승인을 요구하지 않는다.
- 프롬프트, 원고 또는 장면 경계를 바꾸려면 새 리비전과 새 승인이 필요하다.
- 모든 실패 장면이 정상 생성·전달되면 작업을 `DELIVERED`로 전환한다.

### 10. 텔레그램 전달

- 장면 번호 순서로 전송한다.
- 설명에는 작업 ID, 리비전, `장면 N/전체`, 원고 일부를 포함한다.
- 텔레그램 설명 길이 제한을 넘으면 원고 일부를 줄이되 작업 ID와 장면 번호는 유지한다.
- 마지막에 전체 성공 수, 실패 수, 로컬 이미지 폴더를 요약한 완료 메시지를 보낸다.
- 이미지 재전송 시 이미 전달된 장면 메시지 ID가 있으면 건너뛴다.

## 예외 처리

| 상황 | 처리 |
| --- | --- |
| 승인 불일치 | 생성 0회, 상태 변경 없이 오류 보고 |
| ImageGen 사용 불가 | `APPROVED`로 되돌리고 재개 안내 |
| 첫 생성 실패 | 같은 프롬프트로 1회 재시도 |
| 두 번째 생성 실패 | 장면 `FAILED`, 작업 `NEEDS_REVIEW` |
| 파일 저장 실패 | 해당 결과를 전달하지 않고 실패 처리 |
| 이미지 형식 불명 | 파일 저장 금지, 생성 실패로 처리 |
| 텔레그램만 실패 | 로컬 파일과 `GENERATED` 유지, 전달만 재시도 |
| 일부 장면 실패 | 성공 장면 보존·전달, 실패 목록 보고 |
| 승인 후 프롬프트 변경 | 승인 무효, 새 리비전 요구 |

## 완료 기준

- 승인 게이트를 통과하기 전 ImageGen 호출이 없다.
- 모든 장면은 보고서와 같은 번호·프롬프트로 생성된다.
- 정상 이미지는 리비전별 폴더에 보존되고 텔레그램으로 전달된다.
- 장면당 생성 시도는 최대 두 번이다.
- 부분 실패 후 정상 결과를 덮어쓰지 않고 실패 장면만 복구할 수 있다.
- 전체 장면이 전달된 경우에만 작업이 `DELIVERED`가 된다.
