# 텔레그램 승인 워크플로

## 목적

로컬에서 완성한 보고서를 전용 텔레그램 그룹에 전달하고, 등록된 담당자가 현재 보고서에 남긴 답장을 안전하게 조회·분류한다. 이 문서의 승인 결과가 이미지 생성의 유일한 권한 근거다.

## 선행 조건

- `job.json`의 현재 리비전 상태가 `DRAFT` 또는 `SENT_FOR_APPROVAL`이다.
- 현재 리비전의 `report.md`가 존재하고 읽을 수 있다.
- 텔레그램 봇이 대상 그룹에 추가되어 메시지와 파일을 보낼 권한이 있다.
- 로컬 환경에 필수 환경변수가 설정되어 있다.

## 확정 요구사항

### 환경변수

| 변수 | 형식 | 용도 |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | 비밀 문자열 | Bot API 인증 |
| `TELEGRAM_CHAT_ID` | 정수형 문자열 | 전용 그룹 식별 |
| `TELEGRAM_APPROVER_IDS` | 쉼표로 구분한 정수 목록 | 승인 가능한 사용자 허용 목록 |

- 값의 앞뒤 공백을 제거한다.
- 승인 담당자 ID가 하나도 없으면 설정 실패다.
- 토큰은 로그, 보고서, 오류 상세에 출력하지 않는다.
- 저장소에는 변수명만 있는 `.env.example`을 제공한다.

### 도구 명령 인터페이스

텔레그램 스크립트는 다음 네 하위 명령을 제공한다.

| 명령 | 입력 | 성공 결과 | 상태 변경 |
| --- | --- | --- | --- |
| `preflight` | 환경변수 | 봇 ID, 그룹 접근 여부, 허용 담당자 수 | 없음 |
| `send-report` | `job.json`, 리비전 | 요약 메시지 ID, 보고서 파일 메시지 ID, 전송 시각 | `SENT_FOR_APPROVAL` |
| `check-replies` | `job.json`, 리비전 | 유효·무효 답장 메타데이터와 원문 | 스크립트 자체는 없음 |
| `send-images` | `job.json`, 리비전, 이미지 경로 | 장면별 메시지 ID | 장면 전달 결과 반영 |

텔레그램 도구는 자연어 승인 의미를 최종 결정하지 않는다. 원시 답장과 검증 가능한 메타데이터를 반환하고, `devotional-shorts` 스킬이 분류 규칙에 따라 판정한다.

### 사전 점검

`preflight`는 다음을 순서대로 확인한다.

1. 필수 환경변수 존재와 형식
2. `getMe`를 통한 봇 토큰 유효성
3. 대상 그룹 정보 조회 가능 여부
4. 봇의 메시지·문서·이미지 전송 가능 여부
5. 승인 담당자 허용 목록이 비어 있지 않은지

실제 테스트 메시지는 보내지 않는다. 권한을 API만으로 확정할 수 없으면 `send-report` 단계에서 실패를 명확히 보고한다.

### 보고서 전송

텔레그램에는 다음 두 항목을 순서대로 보낸다.

1. 검토 요약 텍스트 메시지
2. 전체 `report.md` 파일

요약 메시지에는 다음 정보를 포함한다.

- 작업 제목 또는 본문 위치
- 작업 ID와 `rNNN` 리비전
- 핵심 묵상 문장
- 선택된 오프닝 질문
- 선택된 썸네일 문구
- 예상 낭독 시간
- 이미지 예상 장면 수
- 분량 예외 및 검토 주의사항
- 현재 메시지에 직접 답장해야 한다는 안내
- 사용할 수 있는 판단: 승인, 수정 요청, 보류

요약이 텔레그램 텍스트 제한을 넘지 않게 상세 콘텐츠는 `report.md`에 둔다. 승인 기준 메시지는 요약 메시지이며 그 메시지 ID를 `report_message_id`로 저장한다.

### 보고 재전송

- `보고 재전송 [작업 ID]`는 현재 리비전의 내용을 변경하지 않는다.
- 새 요약 메시지와 보고서 파일을 보내고 새 요약 메시지 ID를 현재 승인 기준으로 저장한다.
- 이전 보고 메시지에 달린 답장은 즉시 승인 대상에서 제외한다.
- 이벤트 로그에 이전·새 메시지 ID와 재전송 시각을 기록한다.

### 답장 조회와 유효성 검증

`승인 확인 [작업 ID]` 실행 시 다음 순서로 처리한다.

1. 작업과 현재 리비전을 읽는다.
2. 현재 상태가 `SENT_FOR_APPROVAL`인지 확인한다.
3. 보고 전송 시각이 24시간 이내인지 확인한다.
4. 저장한 다음 조회 지점 이후의 텔레그램 업데이트를 가져온다.
5. 대상 그룹의 메시지만 남긴다.
6. 현재 `report_message_id`에 직접 답장한 메시지만 남긴다.
7. 발신자 ID가 `TELEGRAM_APPROVER_IDS`에 포함된 답장만 유효 후보로 남긴다.
8. 원문과 메시지 메타데이터를 스킬에 전달한다.
9. 처리한 마지막 `update_id`를 저장해 중복 처리를 방지한다.

무효 답장도 이유와 함께 이벤트에 남기되 승인 결정에는 사용하지 않는다.

### 자연어 응답 분류

스킬은 유효 답장을 개별적으로 다음 네 범주 중 하나로 분류한다.

| 분류 | 판단 기준 | 결과 |
| --- | --- | --- |
| `approved` | 현재 원고와 장면 구성을 그대로 진행하라는 명확한 의사 또는 `/approve`, `/approve@봇사용자이름` 명령 | 승인 후보 |
| `revision_requested` | 문장, 해석, 이미지, 분량 등을 변경하라는 요구 | 새 리비전 필요 |
| `hold` | 보류, 대기, 나중에 결정하겠다는 의사 | 진행 중지 |
| `unclear` | 감상, 질문, 모호한 긍정처럼 진행 의사가 확정되지 않음 | 상태 유지 |

분류 우선순위는 `revision_requested` → `hold` → `approved` → `unclear`다. `수정해서 진행`, `이 부분 바꾸면 승인`처럼 승인 표현과 수정 조건이 함께 있으면 수정 요청이다.

Privacy Mode가 켜진 그룹에서는 현재 요약 메시지에 직접 답장하여 `/approve@봇사용자이름`을 보내는 방식을 표준 승인 명령으로 사용한다. 명령에 수정 또는 보류 문구가 함께 있으면 각각 `revision_requested`, `hold`가 우선한다.

현재 보고서에 대해 여러 담당자의 답장이 있으면 다음 집계 규칙을 적용한다.

1. 수정 요청이 하나라도 있으면 `REVISION_REQUESTED`다.
2. 수정 요청은 없지만 보류가 하나라도 있으면 `HOLD`다.
3. 수정·보류가 없고 명확한 승인이 하나 이상이면 `APPROVED`다.
4. 그 밖에는 `SENT_FOR_APPROVAL`을 유지한다.

### 수정 요청 처리

- 답장 원문을 `approval.feedback`에 보존한다.
- 현재 리비전 상태를 `REVISION_REQUESTED`로 설정한다.
- 이미지 생성은 호출하지 않는다.
- 콘텐츠 워크플로가 피드백의 변경 범위를 분석해 새 리비전을 만든다.
- 새 리비전은 새 보고 메시지를 받아야 하며 이전 리비전 승인은 사용할 수 없다.

### 승인 처리

- 승인된 작업 ID, 리비전, 보고 메시지 ID, 담당자 ID, 승인 시각을 저장한다.
- 상태를 `APPROVED`로 바꾼다.
- ImageGen 호출 직전에 같은 정보를 다시 비교한다.
- 승인 후 스크립트·장면·프롬프트 해시가 달라졌으면 승인을 무효화하고 새 리비전을 요구한다.

### 사용자 명령

| 명령 | 동작 |
| --- | --- |
| `승인 확인 [작업 ID]` | 현재 보고서 답장 조회, 분류, 상태 변경, 승인 시 이미지 단계 시작 |
| `보고 재전송 [작업 ID]` | 현재 리비전을 새 텔레그램 메시지로 재보고 |
| `작업 상태 [작업 ID]` | 현재 리비전, 상태, 보고 시각, 승인·실패 요약 표시 |

작업 ID가 생략되면 승인 대기 작업이 정확히 하나일 때만 그 작업을 사용한다. 후보가 없거나 둘 이상이면 상태를 변경하지 않고 작업 ID 입력을 요구한다.

### 이미지 전달

`send-images`는 생성 성공한 장면만 번호순으로 보낸다. 각 메시지 설명에는 작업 ID, 리비전, `장면 N/전체`, 해당 원고 일부를 포함한다. 파일별 성공 메시지 ID를 반환하며 이미 전달된 장면은 기본 실행에서 건너뛴다.

## 예외 처리

| 상황 | 처리 |
| --- | --- |
| 환경변수 누락 | 네트워크 호출 없이 누락 변수명만 보고 |
| 잘못된 토큰 | 토큰을 마스킹하고 `preflight` 실패 |
| 그룹 접근 불가 | 로컬 보고서 보존, `DRAFT` 유지 |
| 보고 메시지만 성공하고 파일 실패 | 메시지 ID 기록 후 전체 보고 실패로 표시, 재전송 요구 |
| 24시간 초과 | 답장을 승인으로 처리하지 않고 재전송 안내 |
| 등록되지 않은 사용자 답장 | 무효 이벤트 기록, 상태 유지 |
| 이전 보고 메시지 답장 | 무효 이벤트 기록, 상태 유지 |
| 모호한 답장 | `SENT_FOR_APPROVAL` 유지, 원문 표시 |
| API 일시 실패 | 지수형 대기 없이 현재 명령에서 최대 한 번 즉시 재시도 후 종료 |
| 텔레그램 전달 일부 실패 | 성공 메시지 ID 보존, 실패 장면만 재전송 가능 |

## 완료 기준

- `preflight`가 설정 오류를 메시지 전송 전에 발견한다.
- 보고서 전송 결과와 현재 승인 기준 메시지 ID가 저장된다.
- 등록 담당자가 현재 요약 메시지에 직접 답장한 경우만 판정한다.
- 수정·보류가 승인보다 안전하게 우선한다.
- 승인 확인을 반복해도 같은 답장이나 이미지를 중복 처리하지 않는다.
- 승인 이외의 결과로 ImageGen이 호출되지 않는다.
