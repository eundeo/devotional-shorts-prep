# Devotional Shorts Prep 운영 런북

## 운영 전 확인

1. 플러그인 버전이 `1.0.1`인지 확인한다.
2. 실제 작업은 임시 폴더가 아닌 접근 통제된 영구 프로젝트에서 실행한다.
3. `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_APPROVER_IDS`를 Codex가 실행되는 로컬 환경에 설정한다. 값을 대화, 문서, 로그, 작업 파일에 복사하지 않는다.
4. 이 플러그인만 사용하는 전용 Telegram 봇과 테스트 그룹을 준비한다.
5. 다음 명령을 실행하고 `webhook_configured: false`, 전송 권한, 승인자 수를 확인한다. preflight는 메시지를 보내지 않는다.

```bash
python3 <설치된-플러그인>/scripts/telegram_bot.py preflight
```

outgoing webhook이 있으면 플러그인이 중단한다. 기존 webhook을 자동 삭제하지 말고 소유자와 조정하거나 전용 봇을 사용한다.

## 안전한 승인 운영

- 봇당 `SENT_FOR_APPROVAL` 작업은 하나만 허용한다. 새 보고 전 기존 작업을 승인, 수정 요청 또는 보류로 정리한다.
- 승인 확인 명령은 한 장치·한 세션에서만 실행한다. 동일 작업 폴더를 여러 프로세스가 동시에 수정하지 않는다.
- 담당자는 현재 요약 메시지에 직접 답장한다. 보고 후 24시간이 지나면 보고를 재전송한다.
- Telegram 요약과 첨부 `report.md`의 `검토 메모 → 확인이 필요한 사항`을 함께 검토한다.
- 이미지 생성 전 현재 리비전, 승인 메시지, 장면 수와 예상 생성량을 확인한다.

## 장애 복구

| 증상 | 조치 |
| --- | --- |
| 환경변수 누락 | 같은 실행 환경에 세 변수를 설정하고 preflight 재실행 |
| webhook 충돌 | 기존 연동 소유자와 조정하거나 전용 봇 사용 |
| 다른 승인 대기 작업 존재 | 기존 작업을 먼저 승인·수정 요청·보류 처리 |
| Telegram 429 | 오류가 안내한 `retry_after` 초 동안 재실행하지 않음 |
| 전송 중 네트워크·5xx 응답 유실 | 그룹의 실제 메시지와 로컬 상태를 대조한 뒤 재전송 여부 결정 |
| 보고서 파일 전송만 실패 | 같은 `send-report` 명령으로 저장된 요약 뒤 파일만 재시도 |
| 이미지 전달 일부 실패 | 작업 상태 확인 후 `deliver`를 재실행해 미전달 장면부터 재개 |
| 작업 무결성 실패 | 자동 진행 중단, 백업과 이벤트를 검토하고 `NEEDS_REVIEW` 유지 |

전송 요청은 서버에서 처리됐지만 응답만 유실될 수 있다. 이 경우 외부 시스템의 정확히 한 번 전송을 보장할 수 없으므로, 실제 그룹을 확인하기 전에 명령을 반복하지 않는다.

## 작업 데이터와 백업

- `jobs/`에는 원고, 보고서, 방법론 스냅샷, 이미지, 담당자 답장 원문과 사용자 ID가 포함될 수 있다. 공개 저장소나 배포 ZIP에 넣지 않는다.
- 운영 책임자는 최소 주 1회, 그리고 `DELIVERED` 직후 전체 `jobs/<job-id>/`를 접근 통제된 보관소에 복사한다.
- 기본 보존 기간은 전달 완료 후 90일이다. 법적·조직 정책이 더 길거나 짧으면 해당 정책을 우선하고, 삭제는 운영자의 명시적 절차로 수행한다.
- 월 1회 복원 시험을 수행하고 복원본을 다음 명령으로 검증한다.

```bash
python3 <설치된-플러그인>/scripts/job_store.py validate \
  --project-root <복원-프로젝트> \
  --job-id <작업-ID>
```

인수 기록에는 날짜, 플러그인·방법론·스키마 버전, 작업 ID, 최종 상태, 검증 결과만 남긴다. 토큰과 실제 환경변수 값은 기록하지 않는다.

## 배포 인수

배포자는 ZIP, `.zip.sha256`, `marketplace.json`을 한 묶음으로 전달한다. 수신자는 체크섬 확인, 격리 설치, 새 Codex 세션 시작, 로컬 DRAFT 생성, 테스트 그룹 preflight와 승인 흐름을 차례로 확인한다. 공개 배포 완료로 표시하려면 배포 원격, 태그, 릴리스 자산과 수신자 인수 기록이 모두 있어야 한다.
